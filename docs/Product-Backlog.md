# Digital Marketplace Platform - Product Backlog

## 1. Introducción

El Product Backlog es una lista priorizada de funcionalidades, mejoras y requisitos del proyecto Digital Marketplace Platform.  
Se organiza bajo metodología Scrum y permite planificar el desarrollo iterativo del sistema.

## 2. Objetivo del Backlog

Definir y priorizar las historias de usuario necesarias para construir una plataforma digital segura, escalable y fácil de usar para compradores, vendedores y administradores.

## 3. Historias de Usuario Priorizadas

| ID | Historia de Usuario | Prioridad | Sprint |
|-------------------------------------------------------------------------------------------------------------------|
| US-01 | Como usuario, quiero registrarme para acceder a la plataforma. | Alta | Sprint 1 |
| US-02 | Como usuario, quiero iniciar sesión para acceder a mi cuenta. | Alta | Sprint 1 |
| US-03 | Como comprador, quiero buscar productos por categoría para encontrarlos fácilmente. | Alta | Sprint 2 |
| US-04 | Como comprador, quiero agregar productos al carrito para comprarlos después. | Alta | Sprint 2 |
| US-05 | Como comprador, quiero realizar pagos seguros para completar mis compras. | Alta | Sprint 3 |
| US-06 | Como vendedor, quiero publicar productos para ofrecerlos en la plataforma. | Media | Sprint 3 |
| US-07 | Como vendedor, quiero editar mis productos para mantener la información actualizada. | Media | Sprint 4 |
| US-08 | Como administrador, quiero gestionar usuarios para controlar accesos y permisos. | Alta | Sprint 4 |
| US-09 | Como administrador, quiero monitorear transacciones para garantizar seguridad. | Alta | Sprint 5 |
| US-10 | Como usuario, quiero recibir notificaciones sobre mis pedidos. | Media | Sprint 5 |

## 4. Criterios de Aceptación

### CA-01 Registro de Usuario
- El sistema debe permitir registrar nuevos usuarios.
- Debe validar correo único.
- Debe almacenar contraseña cifrada.

### CA-02 Inicio de Sesión
- El sistema debe autenticar credenciales válidas.
- Debe mostrar mensaje de error si son incorrectas.

### CA-03 Búsqueda de Productos
- Debe filtrar productos por categoría.
- Debe mostrar resultados relevantes.

## 5. Priorización General

**Alta:** Funcionalidades esenciales para operación básica.
**Media:** Funcionalidades importantes pero no críticas.
**Baja:** Mejoras futuras.

## 6. Conclusión

El Product Backlog servirá como base para organizar el trabajo, o trabajo en equipo y asegurar la entrega progresiva de valor en cada sprint.
